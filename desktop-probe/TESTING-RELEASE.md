# Zator — тестовый релиз @RELEASE_TAG@

Pre-release для проверки сборки, обновления роутера и Windows-приложения.
Исходный commit: `@COMMIT@`. Обычный канал `latest` не изменён.

## Что скачать

- `zator-full.tar.gz` — Zator и WebUI для роутера. `core` и `webui` — отдельные варианты штатного обновления.
- `zator-desktop-probe-windows-x64.zip` — готовое portable-приложение, Electron и лицензии. Распаковать **всю папку**, запустить `ZatorDesktopProbe.exe`. Node.js и Go на компьютере не нужны.
- `zator-desktop-probe-router.tar.gz` — опциональный агент: Linux arm64, ARMv7 (`arm`), MIPS/MIPSLE softfloat и amd64, установщик и пример настроек. В основной tar он не включён и автоматически не устанавливается.
- `SHA256SUMS`, отдельные `.sha256` и манифесты — проверка скачанных файлов.

## Обновление Zator

Сохранить резервную копию штатным меню. На роутере со штатным актуальным launcher:

```sh
z2r --version=@RELEASE_TAG@
```

Это установка конкретного тестового релиза, с закреплением версии. Действуют обычные правила применения config.default, сохранения пользовательских файлов и рестарта сервиса. Альтернативный путь — штатная установка скачанного `zator-full.tar.gz` через `z2r --tar /tmp/zator-full.tar.gz`.

Для отката использовать резервную копию или предыдущий номерной релиз. Не менять канал `latest` ради этого теста.

## Агент для приложения

Windows-приложению нужен установленный агент и вход на роутер по SSH-ключу. Обычное обновление Zator не заменяет опциональный агент.

Для уже настроенного компонента распаковать router-архив в отдельную папку, убедиться, что сканирование остановлено, и выбрать бинарник **под архитектуру роутера**. Например, для ранее проверенного ARM64 OpenWrt:

```sh
cd /tmp
tar -xzf zator-desktop-probe-router.tar.gz
cd zator-desktop-probe-router
sh install-router.sh install ./zator-desktop-probe-linux-arm64 /opt/zator/desktop-probe.json
```

Установщик обновляет только компонент и его собственный transport. При первой установке сначала проверить `settings.example.json` и конфликты queue/UID/marks/port по README агента; пример не является готовой конфигурацией для любого роутера. OpenWrt firewall hook подключается отдельно по README. Не копировать бинарник ARM64 на MIPS/ARMv7.

## Проверка Windows

Цели ручной проверки — Windows 10 x64 и Windows 11 x64. Нужен доступный `ssh.exe` (Windows OpenSSH Client), проверка: `ssh -V`. Приложение portable, не подписано; совместимость со всеми сборками Windows ещё не подтверждена. Windows 7/8/8.1 не поддерживаются современным Electron: https://www.electronjs.org/blog/windows-7-to-8-1-deprecation-notice.

Проверить запуск, SSH/проверку ключа роутера, сворачивание настроек, маленький и раскрытый preview, отмену и повторный запуск. Затем короткий проход и полный скан; экспортировать JSON. Для отчёта об ошибке приложить версию Windows, модель/ОС роутера, архитектуру, тег этого релиза и JSON без приватных URL/учётных данных. Пароли и приватные ключи не передавать.

Проверка ограничена IPv4 TCP/HTTPS. Discord в полном скане — публичная страница загрузки; голос/UDP и работа авторизованного клиента не подтверждаются. Физические Keenetic/Entware, 128 МБ и выполнение на MIPS/ARMv7 пока не проверены.
