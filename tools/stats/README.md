# Подсказки из Redis

Роутер получает `GET /z4r/recommendations.tsv?provider=…` с сервера статистики,
без GitHub и без скачивания сырых прогонов. CLI и WebUI используют один кеш
`extra_strats/cache/recommendations.tsv`: 24 часа, включая неудачные запросы.
Обновление ленивое; старые данные при сбое сохраняются с предупреждением.
Ответ ограничен 8 КБ и 17 строками. В главное меню сетевой запрос не добавлен.

## Выборка

- Только завершённые суперсвипы с полной матрицей всех четырёх блоков.
  `state=applying` допустим: клиент отправляет архив до интерактивной сводки.
  Прерванные, неполные и summary-only архивы не участвуют.
- Провайдер определяется по бренду, точным алиасам и известным ASN из
  `data/providers/asn.txt`. Город не дробит выборку; неизвестные ASN не угадываются.
- Порог — 10 разных UUID. Для топа берётся последний завершённый прогон
  каждого UUID для провайдера: частые повторные загрузки не увеличивают его вес.
- По каждому блоку — до трёх стратегий с ненулевым зелёным результатом,
  сортировка по доле зелёных проверок, затем по числу UUID и номеру стратегии.
  `samples` стратегии — число UUID, а не доменных проб; в RKN один UUID
  проверяет несколько доменов. Успешность считается по всем доменным пробам.
- Clone/classic сравниваются отдельно по каждому блоку: последний завершённый
  прогон UUID в каждом режиме, сумма зелёных / сумма всех проб, не среднее процентов.
  Подсказка о клонах появляется только при строго большей успешности и минимум
  трёх UUID в каждом режиме (плюс общий порог 10). Без метаданных режима — classic,
  как в клиенте до появления clone. Включённому clone подсказка не показывается.
- Номера стратегий между версиями конфигурации могут измениться; архив пока не
  содержит версии схемы стратегий. Версия zapret2 её не заменяет. WebUI отбрасывает
  номера вне текущего диапазона и никогда не применяет рекомендации автоматически.

## Сервер

`recommendations.py` устанавливается рядом с существующим `/opt/z4r-stats/server_redis.py`.
`server_redis.patch` — точечная интеграция нового публичного GET, не замена коллектора.
База `asn.txt` устанавливается рядом с ними, либо путь задаётся через
`Z4R_STATS_PROVIDER_ASN`. Существующие маршруты/авторизация коллектора не меняются.

Добавление к nginx snippet:

```nginx
location = /z4r/recommendations.tsv {
    proxy_pass http://127.0.0.1:17683/recommendations.tsv$is_args$args;
}
```

Перед применением: резервные копии коллектора и snippet, проверка патча на текущей
версии, `python3 -m py_compile`, `nginx -t`. После рестарта коллектора и reload nginx:
проверить `/z4r/health` и новый endpoint через внешний клиент.

Redis хранит один компактный агрегат всех провайдеров с TTL 86400 секунд.
Холодный запрос читает существующий индекс и хеши через pipeline; последующие
запросы любых провайдеров читают только агрегат. Refresh защищён process/Redis
замком с lease и атомарной публикацией. Никакие UUID/домены не возвращаются клиенту.
Ограничение существующего хранилища — последние 500 загрузок. Для более длинной
истории нужно расширить retention коллектора или поддерживать накопительный
агрегат при загрузке; роутер менять не потребуется.

## Проверки

```sh
python tests/recommendations_server_test.py
ZATOR_STATS_SERVER=/path/to/server_redis.py python tests/recommendations_server_test.py
bash tests/recommendations_smoke.sh
cd webui-src && node scripts/check-recommendations.mjs && npm run check && npm run build
```

Без `ZATOR_STATS_SERVER` интеграционный HTTP-тест явно пропускается;
остальные серверные проверки независимы от развёрнутого коллектора.
