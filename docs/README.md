# Zator Desktop Probe — пакет заданий для coding-агента

Реализация TCP MVP: [инструкция](../desktop-probe/README.md), [результаты и открытые аппаратные критерии](desktop-probe/RESULTS.md). По указанию пользователя первые испытания выполнены на OpenWrt; физический Keenetic пока недоступен.

**Статус:** план реализации, не подтверждение технической совместимости оборудования.  
**Цель:** десктопное приложение с настоящим браузером, которое проверяет DPI-стратегии через отдельный `nfqws2` на роутере, не вмешиваясь в пользовательский трафик.  
**Целевая первая платформа:** Windows (приложение) + KeeneticOS/Entware (роутер).  
**Дальнейшие платформы:** OpenWrt и Linux, затем полноценные UDP/QUIC-пробы.

## Зафиксированные решения для MVP

- **Не писать новый DPI-движок.** Использовать установленный `nfqws2` и действующие профили/стратегии Zator.
- **Браузер на ПК.** Electron + TypeScript + встроенный `WebContentsView`; CDP/Network для сбора сетевых событий. Никакой установки Chromium на роутер.
- **TCP-трафик браузера через SOCKS5 на роутере.** Браузер подключается к локальному порту ПК, SSH `-L` пересылает его в SOCKS5-сервер, слушающий только `127.0.0.1` на роутере.
- **SOCKS5-процесс работает под отдельным идентификатором ОС** (не под UID тестового `nfqws2`). Именно его исходящие соединения должны направляться в тестовую NFQUEUE.
- **Управление по SSH:** на роутере локальная CLI/RPC-утилита, возвращающая JSON. Не открывать управляющий HTTP-порт в LAN/WAN в MVP.
- **Отдельный `nfqws2`, отдельная NFQUEUE, приватные lock-файлы.** Нельзя менять живые lock-файлы, конфиг, PID/queue или состояние рабочего zapret2.
- **Keenetic: firewall-правила — постоянные на период установки компонента.** Восстанавливать через существующий `/opt/etc/ndm/netfilter.d/000-zapret2.sh`. Запуск/смена стратегии/остановка теста не меняет `iptables`.
- **MVP — TCP/HTTPS/WSS, IPv4.** QUIC/HTTP3, UDP, WebRTC и полноценная эквивалентность LAN-клиенту — зафиксированные ограничения, не объявлять их протестированными.
- **Перед PoC выбрать SOCKS-движок по измерениям.** Проверить отдельный экземпляр `sing-box-lx` (если доступен) и компактный SOCKS fallback; не использовать работающий маwg/sing-box процесс для тестов и не создавать MagiTrickle-группы ради тестов.
- **Сначала технический PoC изоляции на настоящем роутере, затем GUI.** При невозможности достоверной изоляции дальнейшая работа блокируется.

## Соседние проекты: что разрешено переиспользовать

| Проект | Предпочтительное применение | Что **не** делать |
| --- | --- | --- |
| [`MarkinAlexander/sing-box-lx`](https://github.com/MarkinAlexander/sing-box-lx) | Отдельный SOCKS5 ingress + `direct` outbound на роутере для TCP PoC; впоследствии изучить TUN/UDP и наблюдаемость | Не подключать тесты к уже работающему VPN/proxy core, не объявлять gRPC/lxd телеметрию доказательством обработки `nfqws2` |
| [`MarkinAlexander/mawg`](https://github.com/MarkinAlexander/mawg) | Образцы Go-платформенного слоя, сборок MIPS/ARM, lifecycle и read-only получения состояния маршрутов/туннелей | Не переключать production VPN-пулы и не считать `mawg` заменой `nfqws2` |
| [`MarkinAlexander/magitrickle`](https://github.com/MarkinAlexander/magitrickle) | Инспекция текущих policy-routing/DNS-условий; тест совместимости, обнаружение VPN-обхода | Не добавлять/переписывать рабочие группы и маршруты для каждой стратегии |

Все эти зависимости **необязательны**. Решение о внедрении фиксируется в Gate G0 по `EXISTING_PROJECT_REUSE.md`; на роутере с 128 МБ RAM не принимать тяжёлую прокси-зависимость без замеров.

## Основные источники кода Zator

- `lib/supersweep_probe.sh` — создание приватной конфигурации и запуск тестового `nfqws2`.
- `lib/supersweep_transport.sh` — нынешняя маршрутизация проб через Netfilter, её нельзя слепо использовать для нового SOCKS-трафика: существующая привязка рассчитана на исходные порты `62000–62999`.
- `lib/supersweep.sh` — логика фаз, lock-файлов, сбора результатов; **не переносить бизнес-логику целиком**.
- `Entware/000-zapret2.sh` — существующий Keenetic Netfilter hook.
- `lua/locked.lua`, `orchestra/locked.lua`, `config.default` — механика применяемых стратегий.
- `tests/supersweep_transport_smoke.sh`, `tests/supersweep_background_smoke.sh` — регрессионные ориентиры.
- `AGENTS.md` — локальные соглашения проекта, в том числе требования к Keenetic/Entware.

## Как поручить работу агенту

> Реализуй `Zator Desktop Probe` по документам в данном пакете. Не перескакивай через блокирующие критерии этапов 0–2. Начинай с аудита актуального репозитория и связанных mawg/magitrickle/sing-box-lx, обоснуй выбор отдельного SOCKS-движка с учётом RAM/CPU, затем сделай CLI PoC TCP-проверки с отдельной NFQUEUE на физическом Keenetic. После каждого этапа запусти тесты, перечисли изменённые файлы, покажи проверенные инварианты изоляции и явно отметь непроверенное. Не меняй действующие сценарии Supersweep и не перезапускай рабочий zapret2 в процессе тестов. При архитектурных несовместимостях зафиксируй ADR и предложи конкретный обход без скрытого fallback на производственную очередь.

## Правило принятия работы

**HTTP 200, визуально открывшийся сайт или ненулевой счётчик NFQUEUE сами по себе не доказывают работоспособность стратегии.** В каждом подтверждённом результате должны быть привязка к новой тестовой сессии, подтверждение прохождения её трафика через отдельную очередь и достаточно данных для вывода о работе нужного соединения. Ситуации «не смогли проверить» получают `UNKNOWN`, а не `FAIL`.
