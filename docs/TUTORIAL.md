# 🐢 zator — туториал для пользователей

> Гид для тех, кто только поставил zator (или вот-вот поставит) и хочет понять, что вообще происходит, куда нажимать и почему что-то не работает.
>
> **Коротко:** zator ломает блокировки *по домену* (SNI), пряча трафик за «фейковыми» пакетами. Это **не VPN и не прокси** — весь трафик идёт напрямую, без чужих серверов. Блокировки *по IP* он не снимает (об этом — [раздел 9](#9-почему-это-не-поможет-при-блокировках-по-ip)).

## 1. Что такое zator?

**zapret2** — манипулятор пакетами, который в реальном времени проводит автономные атаки на DPI (ТСПУ), чтобы пробить блокировки ресурсов и протоколов. Он ставится на роутер (OpenWRT, Keenetic, Merlin) или на VPS и работает прямо в ядре: перехватывает первые пакеты исходящих соединений и «путает» оборудование провайдера.

**zator** — это обёртка-инсталлятор и менеджер над zapret2. Сам по себе он ничего не блокирует и не разблокирует — он:

- ставит актуальный zapret2 с готовым рабочим конфигом;
- раскатывает проверенные стратегии, хостлисты и фейковые пакеты (блобы);
- даёт удобное меню и WebUI для подбора и фиксации (лока) рабочих стратегий;
- следит за провайдером и показывает рекомендации;
- умеет делать бэкапы и обновляться.

Проект вырос из форка **zapret4rocket** и является его идеологическим продолжением, с ключевым отличием — переходом на **zapret2**.

### Что даёт на практике

- 🎬 YouTube без ограничений
- 🎙️ Голос в Discord
- 📰 meduza.io, ntc.party и другие ресурсы из списка RKN
- 🌐 другие сайты, заблокированные **по домену**

### Чего он не даёт

- ❌ Доступ к ресурсам, заблокированным **по IP** (Instagram и т.п.) — см. [раздел 9](#9-почему-это-не-поможет-при-блокировках-по-ip)
- ❌ Защиту от отравления DNS (нужен DoH/DoT)
- ❌ Шифрование трафика от провайдера (это задача VPN)

## 2. Как это работает

Объясним на пальцах.

**DPI (ТСПУ)** — оборудование провайдера, которое смотрит на начало каждого соединения: какой порт, какой домен (SNI), какой «отпечаток» у клиента. По этим признакам оно решает: пускать соединение или блокировать.

**Идея zapret2** — «сбить с толку» DPI. Перед реальными пакетами отправляются «сломанные»: фейки с неверными контрольными суммами, разрезанные и переставленные реальные пакеты, подделанные заголовки. DPI теряет соединение или перестаёт распознавать домен, а реальная сессия проходит. Сервер при этом фейки игнорирует — они намеренно «невалидные».

```
 Ваше устройство ──► Роутер / VPS ──► DPI (ТСПУ) ──► Сайт
                       │
                       └─ zapret2 (nfqws2 + Lua):
                          перехватывает первые пакеты соединения
                          и «путает» DPI фейками и манипуляциями
```

Теперь чуть точнее, по шагам:

1. **Перехват.** Ядро (iptables/nftables) перенаправляет первые пакеты исходящих соединений на настроенных портах в **nfqws2** — C-ядро zapret2.
2. **Распознавание.** nfqws2 определяет протокол и содержимое: TLS ClientHello, HTTP-запрос, QUIC initial, WireGuard init и т.д., а также домен (SNI / заголовок Host).
3. **Выбор профиля.** Профиль — это пара «фильтр + стратегия»: *какой* трафик обрабатывать и *что* с ним делать. Работает первый совпавший профиль.
4. **Манипуляция.** Lua-функции проводят «атаки»: отправляют фейки, режут пакеты, переставляют, ломают контрольные суммы и т.п.
5. **Применение.** В ручном режиме (по умолчанию) применяется зафиксированная стратегия, а при отсутствии лока — стратегия 1. В авторежиме (пункт 1 → подпункт 10) оркестратор (`circular_quality`) сам перебирает стратегии: не сработала — пробует следующую, сработала — фиксирует (лок).

### Профили, стратегии, локи

| Понятие | Что это |
|---|---|
| **Профиль** | Фильтр: какой трафик обрабатывать. В zator их 9 (таблица в [разделе 6](#6-подбор-стратегии)). |
| **Стратегия** | Нумерованный набор манипуляций пакетами для профиля. Номер стратегии = конкретный рецепт: какой фейк (блоб) слать, где резать пакет, сколько раз повторять. |
| **Лок** | Фиксация рабочей стратегии, чтобы оркестратор её не менял. |

Два режима работы:

- **Ручной режим (по умолчанию).** Стратегии подбираете вы сами (пункт **1** главного меню). Если у профиля нет лока, к нему применяется **стратегия 1**.
- **Авторежим (авторотация).** Включается в пункте **1** → подпункт **10** («Авторотация TCP/HTTP»). Тогда оркестратор (`circular_quality`) сам пробует стратегии по порядку, считает успехи/неудачи, фиксирует рабочие и снимает фиксацию с неработающих. Ручной выбор TCP-стратегий (профили 1–4) и fallback (8/9) в этом режиме недоступен.

## 3. С чем помогает, а с чем нет

| Тип блокировки | zator помогает? |
|---|---|
| **SNI (по домену)** | ✅ Да, это его основной удел |
| **По IP** | ❌ Нет — нужен VPN/прокси, см. [раздел 9](#9-почему-это-не-поможет-при-блокировках-по-ip) |
| **Частичный IP** | ⚠️ Частично, зависит от случая |
| **«16 КБ» (длинный ответ)** | ⚠️ Есть стратегии, нужно подобрать |
| **Отравление DNS** | ⚠️ Нужен DoH/DoT (см. FAQ) |
| **Протокольная (например, UDP)** | ⚠️ Зависит от случая |

## 4. Установка

### Одна команда

```bash
curl -O https://raw.githubusercontent.com/AloofLibra/z4r/z2r/z2r && sh z2r
```

### Что происходит при установке

1. Скрипт определяет ОС и железо (VPS, OpenWRT, Keenetic, Merlin…).
2. Скачивает актуальный zapret2 (GitHub, с зеркалами на случай блокировок).
3. Раскатывает конфиг zator, хостлисты, фейковые пакеты, Lua-скрипты, WebUI.
4. Ставит постоянную команду **`z2r`** — дальше меню открывается просто вводом `z2r`.
5. На VPS спрашивает, ставить ли туннельную панель: **3x-ui, wireguard, 3proxy, marzban** (нужно, если планируете VPN).

> 💡 На все вопросы по пути достаточно **Enter**, если не нужно ничего особенного.

### Требования

- ~**8 МБ** места на диске
- **curl** (если нет: `apt install curl` или `opkg install curl`)
- **Не провайдерский DNS** — поставьте `8.8.8.8` или, лучше, DoH/DoT
- **Offload (ускорение сети) выключен** — с включённым offload zapret2 не работает
- **Keenetic:** в веб-интерфейсе установите компоненты **«Протокол IPv6»** и **«Модули ядра подсистемы Netfilter»**

## 6. Подбор стратегии

Пункт **1** открывает подменю управления стратегиями:

```
--- Управление стратегиями ---
Выбор стратегии профиля (0 или Enter для выхода)
  Текущие стратегии [YT_TLS=auto GV_TLS=auto RKN_TLS=auto DS_TLS=auto
                     YT_QUIC_UDP=auto VOICE_UDP=auto GAMES_UDP=auto
                     FB_TLS=auto FB_HTTP=auto]

  1. Профиль 1: TCP 443 (YouTube) [43]
  2. Профиль 2: TCP 443 (Googlevideo) [43]
  3. Профиль 3: TCP 443 (RKN) [43]
  4. Профиль 4: TCP 443 (Discord) [28]
  5. Профиль 5: UDP 443 (QUIC) [32]
  6. Профиль 6: UDP Voice (Discord/STUN) [32]
  7. Профиль 7: UDP Games (1026-65531) [20]
  8. Fallback TLS (безразборный блок)
  9. Fallback HTTP (безразборный блок) [8]
  10. Авторотация TCP/HTTP [выключен]
  0. Назад
```

В скобках у профилей — максимальный номер стратегии для этого профиля (числа зависят от версии конфига).

### Профили

| № | Профиль | Зачем | Как проверить |
|---|---|---|---|
| 1 | TCP 443 (YouTube) | YouTube по TCP | открыть https://www.youtube.com/ в браузере |
| 2 | TCP 443 (Googlevideo) | Видео YouTube (googlevideo.com) | любое видео в браузере |
| 3 | TCP 443 (RKN) | Сайты из списка RKN | открыть https://meduza.io в браузере |
| 4 | TCP 443 (Discord) | Discord | открыть https://discord.com/ в браузере |
| 5 | UDP 443 (QUIC) | YouTube/Chrome по QUIC | браузер (QUIC включён по умолчанию) |
| 6 | UDP Voice (Discord/STUN) | Голос Discord | приложение Discord |
| 7 | UDP Games (1026–65531) | Игры (BF6, FIFA) | в игре; сначала включите UDP-обход (пункт **10** главного меню) |
| 8 | Fallback TLS | Безразборный режим, TLS | любой заблокированный сайт |
| 9 | Fallback HTTP | Безразборный режим, HTTP | любой заблокированный сайт |

### Как подобрать (пошагово)

1. Выберите профиль (например, **3** — RKN).
2. Введите **номер стратегии** (1…N). **0** — отключить профиль, **Enter** — без изменений.
3. Скрипт применит стратегию и прогонит быструю проверку (curl к тестовому сайту).
4. **Проверьте сайт сами** в браузере/приложении — это важно, curl не всегда видит то, что видит браузер.
5. Скрипт спросит: **`1 - сохранить, 0 - отмена, Enter - далее`**.
   - **1** — зафиксировать стратегию (лок);
   - **0** — отменить и вернуть предыдущее состояние;
   - **Enter** — попробовать следующую стратегию.

Всё. Сработала — сохраняйте. Лок пишется в файл и переживает перезапуски zapret2.

### Что означают статусы

В строке `Текущие стратегии [YT_TLS=auto GV_TLS=auto RKN_TLS=auto ...]`:

- **`auto`** — лока нет: в ручном режиме (по умолчанию) к профилю применяется **стратегия 1**;
- **`N`** (номер) — зафиксирована стратегия N (вручную, или авто-локом в авторежиме);
- **`0`** — профиль отключён (трафик не трогается).

> 💡 Если статусы `auto` и всё работает — не трогайте. Если что-то перестало работать — подберите стратегию вручную (пункт 1) или включите авторотацию (пункт 1 → подпункт 10).

### Подбор под конкретный домен

Пункт **6** (Управление доменами) позволяет добавлять отдельные домены:

- **Исключения (netrogat.txt)** — домены, которые вообще не обрабатывать;
- **TCP_Custom** — отдельные домены со своей стратегией (в WebUI есть кнопка «Подобрать» прямо у домена);
- **Подстроки** — обрабатывать все домены, содержащие заданную подстроку.

## 7. WebUI

Локальная веб-панель на порту **17682**:

```
http://<ip-роутера-или-vps>:17682
```

| Вкладка | Что делает |
|---|---|
| **Статус** | Вкл/выкл zapret2, перезапуск, «Проверить доступ», карточки профилей с текущим локом |
| **Стратегии** | Карточки по каждому профилю: текущий лок, максимум стратегий, форма лока (номер + Сохранить/Сбросить) |

WebUI делает то же самое, что и меню, — просто через браузер. Удобно, если SSH-консоль под рукой не всегда.

## 8. Что такое blob и чем он отличается от sni из первого zapret

Вопрос, который чаще всего путает тех, кто пришёл с первого zapret.

### Как было в zapret 1

Первый zapret — один бинарник с фиксированным набором опций. Вы выбирали режим desync (`--dpi-desync=multisplit`, `--dpi-desync=fake`, …), а для режима фейка — сам фейковый TLS ClientHello (`--dpi-desync-fake-tls=file.bin`).

«sni», который все помнят из первого zapret — это **модификация поля SNI внутри фейкового ClientHello**:

| Опция | Что делала |
|---|---|
| `sni=домен.ру` | заменить SNI в фейке на конкретный домен |
| `rndsni` | заменить SNI на случайный домен |

То есть весь «desync» был фиксированным набором CLI-опций, а подмена SNI — одним из способов сделать фейк «не похожим» на заблокированный домен.

### Как стало в zapret 2

zapret2 разделили на два слоя:

- **C-ядро (nfqws2)** — только перехват, фильтрация, распознавание протоколов, профили, хостлисты. Манипуляции трафиком напрямую оно **не делает**;
- **Lua** — все «атаки» это Lua-функции, вызываемые через `--lua-desync=...`.

**Блоб (blob)** — это бинарный блок (готовый фейковый пакет), который загружается в Lua-переменную при старте:

```
--blob=maxru:@/opt/zapret2/files/fake/tls_clienthello_max_ru.bin
```

Функция `fake` берёт `blob=<имя>` и отправляет этот фейк. Блоб — это «материал» фейка, а стратегия — «рецепт», как его использовать.

Подмена SNI в zapret2 — лишь одна из многих Lua-функций (`snihost`: `sni=домен`, `rndsni`) и больше не центр системы.

**Итого:**

- **zapret 1:** вы «настраивали SNI фейка» — фиксированный набор опций;
- **zapret 2:** вы «выбираете готовый фейк (блоб) и набор манипуляций (стратегию)» — гибкая Lua-сборка.

### Блобы в zator

| Имя | Файл | Что это |
|---|---|---|
| `maxru` | `tls_clienthello_max_ru.bin` | Фейковый ClientHello, «российский» отпечаток |
| `google_www` | `tls_clienthello_www_google_com.bin` | Фейковый ClientHello с отпечатком Google |
| `tls4` / `tls5` | `tls_clienthello_4.bin` / `5.bin` | Варианты фейковых ClientHello |
| `custom` | `custom_tls.bin` | Пользовательский фейк |
| `quic_google` | `quic_initial_www_google_com.bin` | Фейковый QUIC initial (Google) |
| `quic5` | `quic_5.bin` | Вариант фейкового QUIC initial |
| `discord_fake` | `quic_initial_dbankcloud_ru.bin` | Фейковый QUIC initial для Discord |
| `stun_fake` | `stun.bin` | Фейковый STUN-пакет (для голоса) |
| `blob_rdp` | `rdp.bin` | Фейковый RDP-пакет |
| `fakewgblob` | `wg_initial_fake_1.bin` | Фейковый WireGuard init |
| `discord_udp_1/2` | `discord_udp_1.bin` / `2.bin` | Фейки для UDP Discord |

Плюс встроенные в zapret2 стандартные блобы: `fake_default_tls` (ClientHello от firefox, SNI=www.microsoft.com), `fake_default_http` (запрос к www.iana.org), `fake_default_quic`.

В папке `fake/` лежат и другие варианты ClientHello (`tls_clienthello_1…18`, `4pda_to`, `vk_com`, `gosuslugi_ru` и т.д.) — любой из них можно выбрать в пункте **16** (TLS-блоб) или на вкладке «Настройки» в WebUI.

> 💡 **Зачем столько блобов?** Разные DPI по-разному реагируют на разные «отпечатки» клиента. Если один фейк не сработал — пробуют другой.

## 9. Почему это не поможет при блокировках по IP

zapret2 работает с **содержимым** начала соединения: SNI, отпечаток, протокол. Его «атаки» рассчитаны на DPI, которое решает, *что именно* вы открываете.

Если ресурс заблокирован **по IP**, картина иная: пакеты в адрес этого IP просто отбрасываются (или обрываются RST) на уровне адреса — **до** того, как кто-то посмотрит содержимое. Путать DPI нечем: блокировка не зависит от того, что в пакете.

### Что делать с блокировками по IP

- **VPN/прокси** — трафик идёт через ваш сервер, и IP-блокировка становится неважна. На VPS zator прямо при установке может поставить **3x-ui, wireguard, 3proxy или marzban**.
- **DoH/DoT** — если «блокировка» на самом деле отравление DNS.
- **ECH** — зашифрованный SNI; но имейте в виду, что DPI может банить и сам факт наличия ECH.

**Пример:** Instagram в РФ заблокирован по IP, поэтому zator там не поможет — только VPN/прокси.

## 10. Безразборный режим (fallback)

По умолчанию zator обрабатывает только домены из стандартных списков (RKN, YouTube, Discord…). **Безразборный режим** применяет стратегию ко **всем** доменам, а не только к тем, что в списках.

**Когда нужен:** сайт заблокирован, но его нет в списках.

**Как включить:**

1. Пункт **13** (или вкладка «Настройки» в WebUI) — включить режим.
2. В пункте **1** подобрать стратегии для профилей **8** (Fallback TLS) и **9** (Fallback HTTP).

**Нюансы:**

- повышенная нагрузка на CPU;
- может повлиять на сайты, которые работали;
- недоступен, пока включена авторотация TCP/HTTP (пункт 10 в подменю стратегий).

## 11. Другие полезные вещи

### RST-защита (пункт 18)

Защита от инъекций RST: если DPI пытается оборвать соединение поддельным RST-пакетом, zapret2 может его проигнорировать.
Это устаревшая технология, но ещё применяется в некоторых регионах. 

### Игровой UDP (пункт 10)

Включает UDP-обработку портов **1026–65531**. Нужно в основном для игр, но может так же использоваться для работы трекеров, например. После включения подберите стратегию для профиля **7**.

### Фейки WireGuard (пункт 19)

Если вы используете WireGuard, zapret2 может слать несколько фейковых init-пакетов перед реальным, чтобы запутать DPI. Аналогично действует amneziawg. 

### QUIC на 443 (пункт 19)

Подмена initial-пакетов QUIC на порту 443.

### Режим хостлистов (пункт 12)

- `hostlist` (по умолчанию) — только стандартные листы;
- `autohostlist` — zapret2 сам определяет заблокированные домены и добавляет их в лист.

### blockcheck2 (пункт 3)

Детальная проверка стратегий по списку сайтов: тип блокировки (SNI/IP/частичный) и какие стратегии работают. Если ни одна стратегия не работает можно запустить и отправить разработчикам. Выполняется довольно долго. Сохраняет SUMMARY, который нужно приложить к гневному сообщению в канале телеграмм.

### Рекомендации (пункт 15)

Скрипт определяет ваш провайдер и отправляет статистику. Раньше z4r так же давал рекомендации, но для этого нужно чтобы набралась база данных. 
Можно указать провайдера вручную или сбросить автоопределение.

### Порты (пункт 20)

Добавить свои TCP/UDP-порты в перехват. Нужно если приложение/сайт работает на нестандартном порту.

## 12. Типичные проблемы (FAQ)

**В: Я что-то поменял, но не применилось.**
О: Пункт **22** — перезапуск zapret2.

**В: Я куда-то жмал и всё сломалось.**
О: Обновление через 5 пункт без бэкапа сбросит всё к "заводским" настройкам

**В: Обновил стратегии (пункт 5) и потерял рабочую подборку.**
О: Перед обновлением нужно было согласиться создать бэкап. Списки подбора сбрасываются при обновлении.Если бэкап не сделали - ничего страшного, рабочая стратегия обычно находится заново за пару попыток.

**В: Не работает голос в Discord / пинг 5000.**
О: Нужно подобрать "правильную" стратегию в 1 пункте меню. Войсы дискорда работают по UDP, а с ним всегда было сложно. Так же может помочь смена стратегии для TCP Discord. 

**В: На некоторых устройствах ничего не работает.**
О: Проверьте DNS: не провайдерский, `8.8.8.8` или DoH/DoT.

**В: Раньше работало, а теперь нет.**
О: Блокировка изменилась. Запустите пункт **5** (обновить стратегии), затем подберите новые (пункт **1**).

**В: Keenetic не стартует.**
О: В веб-интерфейсе кинетика установите компоненты «Протокол IPv6» и «Модули ядра подсистемы Netfilter». Если не поможет - приходите ныть в группу в телеграм. Поможем чем сможем. 

**В: Что делать с Instagram?**
О: Он заблокирован по IP — zator не поможет, нужен VPN/прокси.

**В: Офлайн (нет доступа к GitHub).**
О: В группе в телеграм в закреплённом комментарии есть инструкция по оффлайн установке

## 13. Глоссарий

| Термин | Значение |
|---|---|
| **DPI / ТСПУ** | Оборудование провайдера, инспектирующее трафик и блокирующее по SNI/IP |
| **SNI** | Имя домена в TLS ClientHello — «адрес», который видит DPI |
| **desync** | «Путание» DPI: сломанные пакеты, чтобы DPI потерял соединение |
| **блоб (blob)** | Бинарный блок (готовый фейковый пакет), загружаемый в Lua |
| **профиль** | Пара «фильтр + стратегия»: какой трафик обрабатывать |
| **стратегия** | Нумерованный набор манипуляций пакетами для профиля |
| **лок** | Фиксация рабочей стратегии |
| **хостлист** | Список доменов, которые обрабатываются |
| **autohostlist** | Автоопределение заблокированных доменов |
| **fallback** | Безразборный режим: стратегия применяется ко всем доменам |
| **QUIC** | Протокол поверх UDP (используют Chrome, YouTube) |
| **nfqws2** | C-ядро zapret2: перехват и фильтрация пакетов |
| **circular_locked** | Оркестратор ручного режима: применяет зафиксированную стратегию, а без лока — стратегию 1 |
| **circular_quality** | Оркестратор авторежима: авторотация стратегий с детекцией успеха/неуспеха (включается в пункте 1 → подпункт 10) |
| **blockcheck2** | Инструмент проверки: тип блокировки и работающие стратегии |
| **ECH** | Encrypted Client Hello — зашифрованный SNI |
