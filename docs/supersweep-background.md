# Фоновый суперавтопрогон

В пункте 12 подменю стратегий после обычных вопросов нажмите **B** вместо Enter.
Меню вернётся сразу; закрытие SSH не останавливает прогон. Повторное открытие
пункта 12 предлагает остановить текущий прогон.

- Лог: `/tmp/z2r-supersweep.log`.
- Прогресс и результаты: `/tmp/z2r-supersweep/` (прежний формат файлов).
- Отмена: `touch /tmp/z2r-supersweep/cancel` либо через меню.
- Обычный Enter сохраняет прежний интерактивный режим.

## Просмотр прогресса и последнего результата

- **CLI:** пункт **13** подменю стратегий. Enter обновляет отчёт, `0` возвращает
  в меню. Просмотр доступен независимо от авторотации и состояния основного nfqws2.
- **WebUI:** раздел **«Стратегии»**, панель **«Суперсвип · прогресс и последний
  результат»**. Во время прогона обновляется каждые 5 секунд, после окончания —
  каждые 15 секунд; есть отдельная кнопка обновления. На скрытой странице
  опрос приостанавливается, при уходе из раздела запрос отменяется.
- Отчёт показывает область применения (`scope`), фазу, счётчики проверок,
  текущую стратегию и цель, зелёные/жёлтые варианты завершённых фаз, результаты
  доменов РКН и **фактически применённых** победителей. Найденный кандидат
  не означает, что он применён; жёлтые результаты отдельно помечены.
- Это история применения **в конкретном прогоне**, а не зеркало текущих локов:
  более поздние ручные изменения смотрите в обычных карточках стратегий.
- После завершения/отмены компактный отчёт атомарно сохраняется в
  `/opt/zator/extra_strats/cache/orchestra/supersweep/last-report.tsv`.
  Он остаётся доступен после очистки `/tmp` и перезагрузки. Если процесс
  аварийно исчез, оставшийся runtime-отчёт показывается как прерванный.
- CLI и CGI используют общий reader из `lib/supersweep.sh`. Просмотр не запускает
  сетевые пробы, не пишет локи и не управляет сервисами. CGI возвращает
  `Cache-Control: no-store`; при ошибке WebUI явно помечает сохранённые на странице
  данные как устаревшие, а не скрывает ошибку.

Снимок создаётся при штатной очистке, в том числе по SIGTERM. SIGKILL или
отключение питания до очистки не могут сохранить новый снимок: если одновременно
потерян `/tmp`, останется предыдущий сохранённый отчёт. Для прогонов до установки
этого обновления persistent-снимок автоматически из старых tar-архивов не строится.

## Накладные расходы CPU

Обработка результата использует встроенный разбор Bash вместо повторных
`cut`/`sed` и подстановок команд. Цветной лог и TSV сохраняют прежний формат;
в новых Bash время берётся через builtin `printf` (для старых есть fallback).
Родитель продолжает обрабатывать ACK и отмену, но не опрашивает завершение
четырёх воркеров на каждой итерации: фазы уже выполняются последовательно.

Поддержка дробного `sleep` определяется один раз и передаётся дочерним процессам.
Если дроби недоступны, интервалы ожидания округляются вверх до целых секунд,
без повторного запуска заведомо неуспешного `sleep 0.3`.

В фоне только воркер Bash и его потомки получают nice 10, если `renice` доступен
и их исходный nice меньше 10. Уже более низкий приоритет не повышается.
Управляющий процесс, основной и тестовый nfqws2 не перенастраиваются;
интерактивный прогон тоже сохраняет исходный приоритет.
Это уступка CPU другим задачам, а не жёсткий лимит нагрузки.

Докачка запускается один раз; повтор — только после неудачи первой попытки.
Успех повтора по-прежнему жёлтый, а не зелёный. TLS 1.2/1.3, пауза чтения
лока и проверки изоляции сохраняются. Ограничение скорости не вводится,
чтобы не искажать сравнение стратегий. `Range` пока остаётся запросом к серверу,
не жёстким локальным лимитом: старые curl не дают безопасного универсального
ограничения неизвестной длины, а отказ до получения тела нельзя считать
успешной проверкой данных.

## Изоляция проб

Из `develop` перенесён принцип изоляции: отдельный nfqws2, отдельная очередь
65535 и локальные TCP-порты curl вне системного ephemeral-диапазона.
Используются текущие стратегии установленного config и обычный locked.lua с
приватными lock-файлами. Для Discord берётся его собственный набор стратегий.
Adaptive Controller, его бинарники, обучение и новые стратегии не переносятся.

Рабочие локи не меняются на каждом тесте. По завершении фазы применяется
найденный зелёный победитель, как в обычном supersweep; жёлтые автоматически
не применяются, включая резервный путь в сводке. Уже применённое сохраняется при
отмене. Пользовательские изменения рабочих локов не откатываются. Основной
сервис не останавливается и не перезапускается из-за остановки фонового теста.
Выбранный client scope передаётся отделённому процессу: победители группы
пишутся в её per-mark файл, а пробные локи остаются приватными/default.
PID из `/tmp/z2r-supersweep.lock/pid` владеет очисткой: SIGTERM ожидает
завершения своего воркера и nfqws2 перед удалением lock и тестовых правил.

Поддержаны iptables и штатные nft-hooks zapret2. При занятой очереди, пересечении
портов/mark, отсутствии подходящего firewall или ошибке nfqws2 прогон прекращается
без переключения проб на основной сервис. Для изолированных TLS-проб отключены
proxy и переходы по редиректам: иначе запрос мог бы выйти из тестовой очереди.
Изоляция не отменяет нагрузку на CPU/канал и возможные ограничения провайдера.
Наличие тестовых правил, счётчик реально прошедших через NFQUEUE пакетов и
ошибки Lua проверяются до/после пробы; HTTP 200 мимо очереди не считается
результатом стратегии. Потеря правил
после перезагрузки firewall отменяет прогон, а не применяет недостоверный результат.
Записи рабочих локов из меню/WebUI/фона сериализованы общим mkdir-lock. После
аварийного завершения владельца может потребоваться удалить оставшийся
`locked.tsv.write-lock` (только убедившись, что писатель больше не работает).

В nft маркировка выполняется в отдельной route/output-цепочке после mangle:
раннюю марку может затереть сторонняя policy routing (проверено с MagiTrickle).
Тестовый nfqws2 использует отдельный числовой UID/GID 65533, без создания
пользователя; занятый UID останавливает запуск. Его raw-сегменты получают ту же
маршрутизацию, что и проба, с сохранением DESYNC_MARK; основной nfqws2 сюда не
попадает. Учтены и пакеты закрытия TCP после исчезновения socket UID.
Произвольные сторонние правила policy routing не заменяются: для такой схемы
нужно отдельно проверить реальный WAN-путь пробы, а не только HTTP-ответ.

Ожидания запуска и блокировки работают с BusyBox без дробного `sleep`.
Приватный план загружает upstream `zapret-auto.lua`: без него `circular_locked`
падает только при обработке первого пакета, даже если dry-run уже прошёл.

Новые модули входят в tar-релизы и `Z2R_LIB_FILES`. Во внешнем лаунчере
`AloofLibra/z4r:z2r` список библиотек обычно получается из GitHub API; для его
аварийного `LIB_FILES_FALLBACK` следует отдельно добавить `supersweep.sh`,
`supersweep_probe.sh`, `supersweep_transport.sh` (лаунчер вне этого репозитория).

Проверки без настоящего firewall/запуска рабочего сервиса:

```sh
bash tests/supersweep_background_smoke.sh
bash tests/supersweep_status_smoke.sh
bash tests/supersweep_frontend_smoke.sh
bash tests/supersweep_transport_smoke.sh
bash tests/orchestra_write_smoke.sh
bash tests/supersweep_smoke.sh
bash tests/tls_check_smoke.sh
```
